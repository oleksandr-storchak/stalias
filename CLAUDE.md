# Alias — правила проєкту

Статична PWA без збірки: HTML + CSS + vanilla JS, IndexedDB для словника,
service worker для офлайну. Нема npm, нема бандлера — файли віддаються як є.

## Додавання слів до словника

`words.json` — це список рядків, який засіває IndexedDB при першому запуску.
Станом на зараз у ньому 5000 слів.

### Правила для слів

- **Тільки іменники** в називному відмінку однини (`молоток`, не `молотки`,
  не `молоткові`, не `кувати`). Виняток — слова, що вживаються лише в множині
  (`ножиці`, `окуляри`, `дріжджі`).
- **Тільки українські.** Русизми не проходять: `творог`, `корзина`,
  `занавіска`, `телега`, `бинокль`, `ботинок`, `тяпка`, `клюшка`. Словник
  ловить більшість із них, але не всі — перевіряй і сам.
- **Тільки кирилиця**, нижній регістр, без пробілів. Одне слово = один запис.
  Латинська літера, що випадково потрапила в українське слово (`гарматa` з
  латинською `a`), — типова помилка; словник її ловить.
- **Без власних назв.** `венера`, `сатурн` з малої літери словник відсіює, і
  це правильна поведінка.
- **Без дублікатів** — звіряй із тим, що вже є у файлі.

### Обов'язковий флоу

Кожне нове слово має пройти перевірку словником. Без цього у файл потрапляють
вигадані слова — сама лише пам'ять моделі тут ненадійна.

1. **Постав hunspell і словник** (одноразово):

   ```sh
   brew install hunspell
   curl -sL -o uk.aff https://raw.githubusercontent.com/LibreOffice/dictionaries/master/uk_UA/uk_UA.aff
   curl -sL -o uk.dic https://raw.githubusercontent.com/LibreOffice/dictionaries/master/uk_UA/uk_UA.dic
   ```

   Клади `uk.aff` / `uk.dic` у scratchpad, не в репозиторій. Запис у
   `~/Library/Spelling/` заблокований пісочницею, тому словник підключається
   шляхом: `hunspell -d /шлях/до/uk` (без розширення).

2. **Напиши кандидатів** у текстовий файл, по темах — так легше тримати
   рівне покриття і бачити прогалини.

3. **Прогони через словник.** `hunspell -l` друкує тільки те, чого в словнику
   немає:

   ```sh
   hunspell -d "$SC/uk" -l < candidates.txt > bad.txt
   ```

4. **Викинь усе з `bad.txt`.** Не «виправляй на око» — або слово проходить
   словник, або його нема. Заміни теж проганяй через `hunspell`.

5. **Злий у `words.json`**, зберігаючи наявний порядок і відсіюючи дублікати:

   ```python
   import json
   bad = {w.strip().lower() for w in open("bad.txt") if w.strip()}
   new = [w.strip().lower() for w in open("candidates.txt") if w.strip()]
   words = json.load(open("words.json")); seen = set(words)
   for w in new:
       if w not in bad and w not in seen:
           seen.add(w); words.append(w)
   json.dump(words, open("words.json", "w"), ensure_ascii=False, indent=2)
   ```

   `ensure_ascii=False` обов'язково — інакше кирилиця перетвориться на
   `\uXXXX`.

6. **Перевір результат цілком** — не лише доданий шматок:

   ```sh
   python3 -c "import json; print('\n'.join(json.load(open('words.json'))))" \
     | hunspell -d "$SC/uk" -l | wc -l   # має бути 0
   ```

   Плюс: кількість, унікальність, відсутність латиниці й пробілів.

7. **Бампни `CACHE_NAME` у `sw.js`** — інакше PWA віддаватиме старий
   `words.json` з кешу.

### Чому `sort -u` не годиться

На macOS `sort -u` без `LC_ALL=C` схлопує кириличні слова в кілька записів.
Дедуплікуй у Python через `set`, а не шелом.

### Досів наявних баз

`dbSeedWords()` у `db.js` не просто засіває порожню базу — він **дораховує
відсутні слова** до вже наявних. Інакше нові слова ніколи б не дійшли до тих,
хто вже грав: стара версія виходила одразу, якщо в базі щось було.

Відомий наслідок: слово, яке юзер видалив через адмінку, досів поверне. База
не розрізняє «ще не було» і «прибрали свідомо». Якщо це почне заважати —
потрібен окремий список видалених.

## Service worker

`CACHE_NAME` у `sw.js` бампається **на кожен деплой**, що змінює будь-який
файл зі списку `urlsToCache`. Обробник `activate` видаляє всі кеші, крім
поточного, тож новий номер витирає старі файли.

Воркер працює network-first: спершу мережа, кеш — лише офлайн-запасний
варіант.

## iOS PWA і safe area

Обидві сторінки використовують `viewport-fit=cover` +
`apple-mobile-web-app-status-bar-style: black-translucent`, щоб градієнт ішов
під статус-бар.

**Тримай `body` простим повноекранним боксом без власного padding.** Safe-area
insets вішай на внутрішній контейнер (`.container` на index, `<section>` на
admin). Padding на самому `body` виштовхує його за viewport, і фон обривається
чорною смугою над home indicator — саме так виглядав баг, який довелося
довго ловити.

`apple-mobile-web-app-status-bar-style` iOS читає **один раз при встановленні**
на home screen. Змінити його для вже встановленої іконки з веба неможливо —
потрібне перевстановлення. Про це варто попереджати, а не обіцяти, що
оновиться саме.

## Стиль коду

- Vanilla JS без фреймворків і збірки. Елементи беруться через
  `window.<id>` — саме так написаний наявний код.
- Коментарі пояснюють **чому**, а не що робить рядок. Тримайся наявної
  щільності — вона висока, але не описова.
- CSS вкладений (nesting), змінні в `:root`. Нові правила клади поруч із
  спорідненими, а не в кінець файлу.
